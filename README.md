# Entity Resolution

Large-scale business entity resolution across three noisy data sources.

For every record in **Source 1**, find all records in **Source 2** and **Source 3** that describe the same business,
even when names are transliterated, abbreviated or misspelled and addresses are reordered or incomplete. The test
set also contains a country (France) that never appears in training.

| result | macro F0.5 |
|---|---|
| **Best build `v13_union`** (hidden test labels, India + US + France) | **0.988** |
| Stacker `v12_mylgbm`, held-out dev (66k labelled S1) | 0.9901 (95% CI 0.9896–0.9905) |
| Level-1 LightGBM alone, OOF | 0.9699 (200k S1) → 0.9805 (all 2.2M S1) |

## The problem

| | |
|---|---|
| Records | 2.2M (S1) / 5.0M (S2) / 5.3M (S3) in train; 1.7M / 4.9M / 5.1M in test |
| Countries | train: India, US · test: India, US **and France (unseen)** |
| Metric | F0.5 per S1 entity, macro-averaged; a singleton (no true match) scores 1 only if nothing is predicted |
| Matches | most S1 have 2–6 matches (mean ≈ 3.5); 5.6% are singletons |
| Structure | strictly one-to-one: an S2/S3 record belongs to at most one S1; true pairs always share a country |
| Noise | legal suffixes anywhere, junk marks, `fka`/`aka` aliases, OCR digit swaps, ~9% of S2 names in Devanagari/Bengali script |

## Architecture

```
                         dataset/  (S1, S2, S3)
                               │
 LEVEL 1  entity_matcher/run.py
   normalize → embed (fine-tuned e5-small) → block (token IDF ∪ GPU kNN, 25 / S1, recall 99.2%)
             → ~70 pair features → LightGBM (5 folds grouped by S1, stage 1 + stage 2)
                               │  candidates + LightGBM probability        → precomputed/full_out
             ┌─────────────────┴──────────────────┐
 LEVEL 2a  cross-encoders                 LEVEL 2b  companion pipeline
   xlm-r base / large / full,               independent blocking + LightGBM with
   Qwen3-4B LoRA, France self-training      candidate expansion       → precomputed/my_lgbm_out
   → precomputed/ce_*                        + its own matches        → precomputed/my_pipeline
             └─────────────────┬──────────────────┘
 LEVEL 3  stacker  (stack_submit → v11, loop_eval --final → v12)
   LightGBM over 6 scores + per-S1 / per-candidate competition context, trained on fold-0 S1s only
   → one-to-one + expected-F0.5 set selection                                → output/v12_mylgbm
                               │
 LEVEL 4  union_submit
   + companion pairs that level-1 blocking missed, S2/S3 record still free   → output/v13_union  (0.988)
   + companion pairs the stacker rejected at p ≥ 0.3                         → output/v14_last
```

Full details, the evaluation protocol and every number behind each choice are in
**[docs/methodology.md](docs/methodology.md)**.

## Repository structure

| path | contents |
|---|---|
| `entity_matcher/` | all pipeline, stacking, assembly and analysis code |
| `configs/` | `default` (200k S1), `large_sample` (500k), `full` (all 2.2M), `smoke` (5k), `experiment` |
| `dataset/` | place the source TSVs here (not redistributed; see `dataset/README.md`) |
| `artefacts/` | stage caches, regenerated by the pipeline; split and experiment reports committed |
| `precomputed/` | level-1 full-data LightGBM, every cross-encoder's scores and the companion scores, with `REPORT.md` per model |
| `output/` | every build v1 → v14_last (`matching_results.tsv.gz` + recipe), final candidates in parts; `output/README.md` |
| `logs/` | `builds.csv` (all builds with validation / test scores), `experiments.csv`, run logs |
| `docs/` | methodology |
| `utils/` | output-format validator |
| `scripts/` | per-country output diff |

Files over 90 MB are stored gzip-split (`*.gz.partNN`) or as several parquet parts; `python output/restore.py` rejoins them.

## Reproduce

Pick one path. Every command runs from the repo root.

### Path A: restore and check the final outputs (5 min)

| # | command | result |
|---|---|---|
| A1 | `python output/restore.py v13_union` | `output/v13_union/matching_results.tsv` + `candidate_pairs.tsv` |
| A2 | `python utils/validate_outputs.py --matching output/v13_union/matching_results.tsv --candidate output/v13_union/candidate_pairs.tsv --test-dir dataset/test --check-ids` | `PASS` |
| A3 | same with `v14_last` | last build |

### Path B: rebuild levels 3 and 4 from `precomputed/` (CPU, ~1 h, 16 GB RAM)

This retrains the stacker and redoes the decision and both union steps, reusing the level-1, cross-encoder and
companion scores in `precomputed/`.

| # | command | what it does | time |
|---|---|---|---|
| B1 | `python -m entity_matcher.run --stage normalize --split train` | cleaned train records (countries, context) | 4 min |
| B2 | `python -m entity_matcher.run --stage normalize --split test` | cleaned test records | 4 min |
| B3 | `python -m entity_matcher.restore_cands` | `artefacts/test/cands.parquet` from `precomputed/full_out`, so no GPU blocking is needed | 1 min |
| B4 | `python -m entity_matcher.splits` | fit / dev / lockbox split of the fold-0 S1s (70 / 15 / 15, seed 42) | 1 min |
| B5 | `python -m entity_matcher.loop_eval --tag E000_champion` | v11 recipe fitted on *fit*, scored on *dev*: bootstrap reference | 10 min |
| B6 | [v12 command](#v12-command) | + companion LightGBM column, scored on dev (expect 0.9901, Δ +0.00034) | 11 min |
| B7 | v12 command + `--final output/v12_mylgbm` | retrain on all fold-0 S1s, predict test, France from v11 → **v12** | 15 min |
| B8 | `python -m entity_matcher.union_submit --base output/v12_mylgbm --out output/v13_union` | + 28,319 companion-only pairs → **v13_union** | 5 min |
| B9 | `python -m entity_matcher.union_submit --base output/v13_union --out output/v14_last --rescue_probs artefacts/exp/E001_mylgbm/final_test_probs.parquet --rescue_min 0.3` | + 10,779 rescued pairs → **v14_last** | 5 min |
| B10 | `python scripts/compare_outputs.py output/v13_union/matching_results.tsv.gz output/v13_union/matching_results.tsv` | per-country diff against the committed file (expect `changed` ≈ 0) | 2 min |

Step B8 overwrites `output/v13_union/matching_results.tsv` next to the committed `.gz`, and B10 compares the two.
Use `git stash` or a copy first if you want to keep a restored file.

<a id="v12-command"></a>
**v12 command** (B6; add `--final output/v12_mylgbm` for B7):

```bash
python -m entity_matcher.loop_eval --tag E001_mylgbm \
  --extra ce_large=precomputed/ce_large_out --extra ce_full=precomputed/ce_full_out \
  --extra qwen=precomputed/ce_qwen_v11 --extra mylgbm=precomputed/my_lgbm_out \
  --fill qwen=ce_full --fill mylgbm=lgbm \
  --eval_fill qwen=ce_full:0.02:0.98 --eval_fill mylgbm=lgbm
```

Optional: rebuild v11, whose France rows v12 keeps (`output/v11_qwen`):

```bash
python -m entity_matcher.stack_submit --out output/v11_qwen --features extra \
  --extra ce_large=precomputed/ce_large_out --extra ce_full=precomputed/ce_full_out \
  --extra qwen=precomputed/ce_qwen_v11 --fill qwen=ce_full \
  --swap ce_large=precomputed/ce_france_out --shift france:-1 --alpha 1.5 \
  --pairs "precomputed/full_out/oof_train_full_part*.parquet" \
  --lgbm_test "precomputed/full_out/probs_model_full_part*.parquet"
```

LightGBM on different CPUs can differ in the last bits, so a handful of near-tie S1s may come out differently.

### Path C: retrain level 1 from raw data (GPU ≥ 8 GB, ~5 h)

| # | command | what it does | time (RTX 4060) |
|---|---|---|---|
| C1 | `python -m entity_matcher.run --stage normalize --split train` (and `--split test`) | name views, canonical addresses, postal / numbers / landmarks | 3 + 3 min |
| C2 | `python -m entity_matcher.finetune_embed --pairs 400000 --max_steps 2500 --out artefacts/embed_ft` | InfoNCE fine-tuning of multilingual-e5-small | 15 min |
| C3 | `python -m entity_matcher.run --stage embed --split train` (and `--split test`) | encode every record to disk memmaps | 45 + 75 min |
| C4 | `python -m entity_matcher.run --stage block --split train` | token + embedding blocking; prints recall per pass and union | 37 min |
| C5 | `python -m entity_matcher.run --stage features --split train` | pair features for the training sample | 3 min |
| C6 | `python -m entity_matcher.run --stage rank --split train` | grouped 5-fold LightGBM stage 1 + 2, decision tuning; prints OOF F0.5 | 60 min |
| C7 | `python -m entity_matcher.run --stage block --split test` | test candidates | 28 min |
| C8 | `python -m entity_matcher.run --stage features --split test` | test pair features | 12 min |
| C9 | `python -m entity_matcher.run --stage rank --split test` | test probabilities | 70 min |
| C10 | `python -m entity_matcher.run --stage decide --split test` | one-to-one + F0.5 set selection → `output/` + validator | 3 min |

`python -m entity_matcher.reproduce [--resume]` runs C1–C10 in one go. `--config configs/full.yaml` trains on all
2.2M S1 (the run behind `precomputed/full_out`), and `--config configs/smoke.yaml` is a 5k-S1 check.

The cross-encoders (level 2a) and the companion pipeline (level 2b) are trained outside this repository. Their
recipes are in `precomputed/*/REPORT.md` and the methodology, and their scores are in `precomputed/`.

## Hardware notes

Level 1 is built for 16 GB of RAM and an 8 GB GPU. Embeddings are streamed to disk memmaps, kNN moves 1M-row pool
chunks onto the GPU, features are written in S1 chunks, and training uses integer ids instead of string sets.
Don't run two heavy stages at the same time. The cross-encoders were trained on an NVIDIA H100.
